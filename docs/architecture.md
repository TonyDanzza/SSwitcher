# Conversion and cancellation

`ConversionCoordinator` owns one main-thread `ConversionAttempt`. The attempt contains its input-generation predicates, cancellation token, lifecycle, original/expected document, clipboard transaction, optional image, deadlines and trace. There is no global mutable conversion state. Only the active attempt may deliver a callback; its lifecycle permits one mutation reservation and one completion. Real input invalidates its token/lifecycle before deferred cleanup. Cancellation before text mutation is distinct from an unverified result after any mutation. Termination uses synchronous main-thread cleanup so clipboard restoration does not depend on another run-loop turn.

`KeyboardMonitor` keeps the listening event callback short: detector/gate counters, generations, modifier tracking, delivery receipts and local cancellation. AppKit overlay cleanup is deferred. `ShiftBurstGate` has idle, pending, running, draining and blocked states. Requests during an attempt never become a queue. The draining state extends on every remaining Shift event until a complete quiet interval. An unverified attempt blocks further mutations until real input/focus changes; a blocked double Shift updates the menu tooltip with the recovery instruction. A physical modifier held before the text mutation refuses the operation. Between Unicode batches, during selected-text restoration and during its non-destructive verification, a repeated Shift may release within a fixed one-second budget before that same attempt continues. Typing, other modifiers, focus changes and secure input still invalidate it immediately.

`PhysicalModifierState` combines unmarked modifier transitions with `CGEventSource.keyState(.hidSystemState, key:)`. Aggregate shortcut flags are deliberately excluded. Live testing found that leaving shortcut flags on a synthetic key-up could leave Command sticky even in HID state checks. Synthetic key-down carries the intended shortcut and key-up clears its flags. The monitor ignores its own marker on synthetic events. A hardware plus tracked-state guard catches a modifier already held when monitoring starts or before initial Copy, Unicode input and selection restoration. Between canvas arrow batches, queued synthetic Shift can still appear in the HID table. That continuation and its final non-destructive verification Copy instead require unchanged input/focus, secure-input checks and clear unmarked tracked modifiers. Repeated physical Shift pauses those boundaries until release or timeout; it never authorizes another mutation. Other physical modifier transitions still cancel. `ModifierReleaseReadiness` fixes the wait's deadline so polling cannot extend it.

`AccessibilityExecution` separates external and local AX calls. A remote `AXClient` serializes synchronous work on one dispatch queue; main never waits synchronously for that queue. A separate main-bound client handles this application's own AX objects, because local AX can invoke AppKit setters and getters directly. Each client owns separate caches, confined to its execution context. System-wide focus discovery runs remotely and does not read this application's focused view there. Both clients configure the messaging timeout on every acquired AX object, batch initial attributes, and narrow repeated confirmation to value/range. CFNull, AXError and wrong AXValue types are decoded safely. The main continuation checks input generation, process activation, secure input and physical modifiers again after remote validation, immediately before posting the prepared event sequence.

An AX setter is a synchronous message to another process. The selected-range path checks cancellation before validation and immediately before the single setter, then verifies range/document and actual Copy. An already in-flight IPC cannot be revoked by a later input event. This is an OS boundary, not a guarantee of atomicity across two applications. No native setter is used for word mode or Figma canvas.

The old asynchronous Command+V path could outlive its clipboard payload: cancellation, timeout or verification Copy could replace the pasteboard before the target consumed Paste. A session-tap receipt does not acknowledge that consumption, so extending a timeout cannot solve this ordering problem. Version 0.1.9 removes that transport.

`UnicodeTextInput` embeds replacement text in private-source keyboard events with virtual key 0. It creates all events and verifies their exact UTF-16 payloads before the one mutation reservation. Each ordinary text event contains at most 20 UTF-16 units, preserving whole extended grapheme clusters; an oversized cluster is refused before mutation. Word Backspace events and the first text pair share one prebuilt batch, without changing the selection. The final key-up receipt gates the next batch, with an additional 8 ms gap between pairs. A held repeated Shift waits within the existing bounded modifier budget. Cancellation stops unposted batches, but an already-posted batch cannot be revoked.

No replacement path emits Command+V or writes the converted text to the general pasteboard. Word mode does not touch the pasteboard. Selected mode uses it only to read and verify the actual selection, saving all original formats and restoring them only while the transaction still owns the current revision. Initial Copy must equal nonempty AXSelectedText or a substring from a coherent document/range; absent independent evidence, the attempt stops before Copy or mutation. A mismatching or rejected clipboard revision is never adopted or overwritten. A late Copy can still publish after cancellation; this residual clipboard limitation no longer changes an event's replacement payload.

Control characters need demonstrated editor behavior. Figma's proven canvas text editor (`AXTextArea` with description `Text`, checked again during preflight) uses Return for LF and Shift+Return for U+2028; its initial Copy must also match independent character-selection evidence. Figma comments/property fields do not receive this policy. The application's own tested NSTextView accepts literal Unicode line characters. Other applications currently refuse LF/U+2028 before mutation. CR, tab, other control scalars and U+2029 are refused everywhere. Unicode event support has no general per-field capability query: a framework may translate the virtual key instead of using its Unicode string. Actual editor proof remains required, and an unverified mutation never triggers a paste fallback or another mutation.

`EditorCompatibilityPolicy` centralizes Figma's transient focus and mirror behavior. A native selected replacement requires full-document acknowledgement before restoring its selected range once. This avoids the previous per-character selection rendering for long selections. Figma uses a single Command+A only when its coherent original range covers the complete document and the independently copied selection equals that document. Partial, missing or mismatching evidence retains exact Shift+Left restoration in 32-character batches. A confirmed whole-document scope may be reused for reversal only for the same process session and AX element with unchanged input. No partial selection is widened based on a guessed word or line boundary.

Every keyboard event source carries the synthetic marker. Each Unicode/canvas batch's final key-down/up pair carries a distinct delivery marker through a separate `CGEventSource.userData`. Live Quartz delivery normalized per-event markers back to the original source marker, so changing only an event field is insufficient. Only the tagged final key-up's receipt at the listening session tap releases the next batch, with a 500 ms watchdog and cancellation cleanup; a late marker from an old batch cannot release a new one. This establishes passage through Quartz, not target-editor handling. Word mode and native atomic range restoration still require the expected document; other selected mode requires exact actual Copy. Canvas selection restoration starts after final text delivery, without the old 320 ms paste fallback: Figma's AXValue can normalize LF paragraphs differently from its actual selected text. Actual Copy must still return exactly the converted text. Initial Copy and text mutation are never retried. Canvas verification alone may issue up to three non-destructive Copies within one 500 ms deadline after the first safe modifier release. A proper suffix of the expected replacement or a late original Copy can trigger another verification Copy. Missing plain text or a clipboard revision changing during the read remains pending within that deadline, without adopting ownership or sending another Copy. An unrelated stable mismatch is never adopted as clipboard ownership, and a newer clipboard revision between a transient result and retry aborts without overwriting it. No text mutation or selection-arrow sequence is repeated.

Figma's initial copied text must match independent text-edit selection evidence; layer/object clipboard data is not treated as a character selection. Live testing showed that Copy can clear Figma's AX range while the actual canvas selection stays selected. Selected-canvas preflight therefore uses the matching real Copy, unchanged input/focus and unchanged document, rather than the post-Copy AX range, and checks the canvas role/description before allowing Return. The word path still requires its exact original caret range. One confirmed canvas selection is kept in memory only until real input/focus changes, to support reversal when the AX mirror collapses.

A separate signed test helper checked direct `AXSelectedText` replacement in the current Figma canvas. The attribute reported settable and its setter returned success, but independent Command+C and the visible canvas both retained the original text. That is a false success from the AX mirror, so production never uses that setter for canvas replacement.

Figma exposes an atomic text selection setter through its [plugin API](https://developers.figma.com/docs/plugins/api/properties/PageNode-selectedtextrange/). That API runs inside a Figma plugin and is not an external macOS Accessibility operation. This app has no runtime Figma plugin/server integration, so it cannot promise that long canvas selections redraw atomically.

# Timing policy

All budgets are in `ConversionTiming`. Readiness deadlines stop waiting when evidence arrives; they are not mandatory sleeps.

| Budget | Value | Reason |
| --- | ---: | --- |
| Final Shift-release quiet interval | 90 ms | Conservative reduction from 145 ms; the explicit running/draining states protect interleavings during and after replacement. |
| One AX message | 120 ms | Bounds an unresponsive IPC without blocking UI; each newly acquired object is configured. |
| Copy result / text acknowledgement deadline | 500 ms each | Allows slow editors/providers while refusing an unverified destructive retry. |
| Readiness poll | 20 ms | Temporary, only during an attempt; no permanent text/permission polling. |
| Unicode pair pacing | 8 ms after receipt | Gives the editor turns between bounded text chunks; queue delivery remains separate from editor proof. |
| Unicode/canvas batch delivery deadline | 500 ms | Waits for the matching final key-up at the session tap; target handling still requires expected text or actual Copy. |
| Text/selection modifier-release deadline | 1,000 ms | Allows a rapid repeated Shift to release between batches or at selection boundaries; unchanged input/focus checks remain active. |
| Screenshot delivery budget | 55 ms | Allows typical warm captures while preventing a cold service from adding 100 ms. Geometry IPC is measured separately as AX work. |
| Reveal | 90 ms | Short fade after editor acknowledgement; never included as rendered completion. |
| Visible overlay watchdog | 650 ms | Releases the panel/image even if editor acknowledgement does not arrive. |

An AXObserver is optional according to Apple and notifications may be unsupported. This implementation uses bounded value/range polling instead of registering several notifications on every gesture: observer setup adds IPC and cannot prove success. `ReadinessDeadline` tests demonstrate that repeated polling cannot extend the original deadline; only matching editor evidence establishes success.

`ReplacementOverlay` owns both a pending screenshot delivery and the current nonactivating, click-through panel. `PreparationResult.cancelled` cannot resume mutation; `.skipped` may proceed without an optional animation. Cancellation, timeout and late screenshot completion deliver at most once. Missing/zero geometry, multiline text, offscreen rectangles, secure input, old OS, missing permission and Reduce Motion skip capture. There is no guessed Figma geometry, full-screen screenshot, stream, OCR, disk image or network transport. A closed panel releases its view/image and presenter reference.

# Capability and idle-work bounds

Capability keys contain process identifier, launch session, bundle version and AX element identity. Positive capabilities expire within 30 seconds; unsupported results are short lived. A failed geometry request is scoped additionally to its range, expires after two seconds and is cleared by real input/focus. A canvas failure cannot blacklist a sidebar field. AXManualAccessibility activation is cached per process session for 60 seconds after success or three seconds after failure.

Once input monitoring and Accessibility permission are granted and the tap runs, no permission timer remains. Missing permission/startup triggers at most 15 two-second retries, then recovery occurs on app activation, menu opening or diagnostics opening. Diagnostic updates run only while the window is visible and stop on close/minimize. No text polling runs at idle.

# Measurement and small optional features

`PerformanceRecorder` uses paired OSSignposter intervals for gate, AX operations, capture, event posting, confirmation wait, reveal and gesture-release-to-result. The mutation interval now includes text-pair pacing and queue receipts through the final batch. Each interval state is consumed once; an `EditorAcknowledged` event is emitted only after successful verification. Signposts carry fixed names/identifiers only. Numeric summaries retain 64 samples per metric in up to eight process-session/mode buckets. Median and p95 appear only after 20 confirmed samples in the same bucket. Failed/cancelled attempts do not enter confirmed-replacement distributions. AX duration accumulates AX work in the selected execution context; confirmation includes waiting for the editor. These timings overlap by design and must not be summed as disjoint wall-clock phases.

Editor acknowledgement means an expected document or actual Copy was verified. It does not measure the compositor's completed on-screen frame. Reveal duration reports the overlay, not target-app rendering. No user text, clipboard payload or pixels enter diagnostics or logs.

`LoginAtLaunch` reads `SMAppService.mainApp.status` and mutates registration only after the user presses its menu item. It never registers on launch. Status/approval/error display follows macOS; registration work is dispatched off UI. The diagnostics-copy button writes only the displayed status/timings plus app/OS versions to the user's clipboard, after an explicit click.

# Primary sources and SDK checks

The implementation was checked against these Apple sources and local SDK declarations (`AXUIElement.h`, `AXValue.h`, `CGEventSource.h`, `SCScreenshotManager.h`, `SMAppService.h`, and the `os.swiftinterface`):

- [Improving app responsiveness](https://developer.apple.com/documentation/xcode/improving-app-responsiveness): keep UI responsive and dispatch blocking non-UI work away from main.
- [AXUIElementCopyMultipleAttributeValues](https://developer.apple.com/documentation/applicationservices/1462051-axuielementcopymultipleattribute): per-slot CFNull/AXError results can coexist with a successful batch.
- [AXUIElementSetMessagingTimeout](https://developer.apple.com/documentation/applicationservices/1459345-axuielementsetmessagingtimeout): timeout belongs to the configured object.
- [AXObserverCreate](https://developer.apple.com/documentation/applicationservices/1460133-axobservercreate) and the notification SDK declarations: optional notifications are not confirmation.
- [CGEventSource.keyState](https://developer.apple.com/documentation/coregraphics/cgeventsource/keystate(_:key:)) and [HID state](https://developer.apple.com/documentation/coregraphics/cgeventsourcestateid/hidsystemstate): sample key-down state separately from aggregate flags.
- [CGEvent.tapCreate](https://developer.apple.com/documentation/coregraphics/cgevent/tapcreate(tap:place:options:eventsofinterest:callback:userinfo:)): listening event tap uses its registered run loop.
- [CGEvent.keyboardSetUnicodeString](https://developer.apple.com/documentation/coregraphics/cgevent/keyboardsetunicodestring%28stringlength%3Aunicodestring%3A%29): carries text in the event; Apple warns that a framework may ignore it and translate the virtual key instead.
- [CGEvent.post](https://developer.apple.com/documentation/coregraphics/cgevent/post%28tap%3A%29): posts into the event stream before the selected taps, without acknowledging editor consumption.
- [Timer energy guidance](https://developer.apple.com/library/archive/documentation/Performance/Conceptual/power_efficiency_guidelines_osx/Timers.html): temporary timers, bounded waits and invalidation when no longer needed.
- [OSSignposter](https://developer.apple.com/documentation/os/ossignposter): retain each begin state and pair it with exactly one matching end.
- [SCScreenshotManager](https://developer.apple.com/documentation/screencapturekit/scscreenshotmanager): the region screenshot API is guarded for macOS 15.2+; baseline remains macOS 13.
- [SMAppService](https://developer.apple.com/documentation/servicemanagement/smappservice), [register](https://developer.apple.com/documentation/servicemanagement/smappservice/register()), and [requiresApproval](https://developer.apple.com/documentation/servicemanagement/smappservice/status-swift.enum/requiresapproval): main-app login registration is explicit and can require a System Settings action.
