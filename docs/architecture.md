# Conversion and cancellation

`ConversionCoordinator` owns one main-thread `ConversionAttempt`: input-generation predicates, cancellation token, lifecycle, original document/range, coherent selection and replacement plans, optional image, deadlines and trace. Only the active attempt may resume a callback; its lifecycle permits one mutation reservation and one completion. Real input invalidates the token/lifecycle before deferred cleanup. Cancellation before mutation is distinct from an unverified result after mutation. Termination performs synchronous main-thread cleanup without clipboard work.

`KeyboardMonitor` keeps the listening event callback short: detector/gate counters, generations, modifier tracking, delivery receipts and local cancellation. Overlay cleanup is deferred. `ShiftBurstGate` has idle, pending, running, draining and blocked states. Requests during an attempt never become a queue. Draining extends on remaining Shift events until a complete quiet interval. An unverified attempt blocks further mutations until real input/focus changes. A repeated physical Shift may release within a fixed one-second budget while the same stream/restoration continues. Typing, other modifiers, focus changes and secure input invalidate the attempt immediately.

`PhysicalModifierState` combines unmarked modifier transitions with `CGEventSource.keyState(.hidSystemState, key:)`; aggregate shortcut flags are excluded. Synthetic key-down carries the intended shortcut and key-up clears its flags, avoiding sticky synthetic modifier state observed in live tests. Hardware plus tracked-state guards protect the first mutation and selection restoration. Between batches, synthetic Shift may temporarily appear in HID state; continuation therefore checks clear unmarked tracked modifiers, unchanged input/focus and secure input. `ModifierReleaseReadiness` polling cannot extend the original release deadline.

# Accessibility evidence and clipboard independence

No conversion path reads or writes a pasteboard or sends Command+C/Command+V. The obsolete pasteboard transaction, Copy polling and verified canvas-selection cache were removed. The only production pasteboard access is the explicit diagnostic-report copy button.

`AccessibilityExecution` separates serialized external AX calls from main-bound own-process calls, which can directly invoke AppKit. Each `AXClient` owns isolated caches. Every acquired AX element gets its messaging timeout. Electron manual-accessibility activation is followed by fresh focus discovery; an exposed mirror is not by itself editing proof.

Electron recognition preserves the standard framework path and also recognizes a branded package only with APPL package metadata, the documented `ElectronAsarIntegrity` entry for `Resources/app.asar` (SHA256 and a 64-character ASCII hexadecimal hash), an actual archive file and an immediate FMWK framework with its actual executable. Versioned framework symlinks are resolved. This reads small property lists and file metadata, never the archive contents or its hash. It enables the existing Electron preparation policy; application names and Chromium version metadata alone do not authorize it. A successful `AXManualAccessibility` setter is not tree readiness or editing acknowledgement, so unavailable snapshots still refuse the attempt.

Before AppKit UI, observers or the keyboard tap are constructed, the process acquires a nonblocking `flock` lease in the user's private temporary directory. The descriptor is close-on-exec; symlinks, nonregular files and files owned by another user are refused. The lease stays alive through `app.run()` and its pathname is never unlinked, preventing concurrent claims on different inodes. A finished, nonterminated app with the same bundle identifier also refuses startup, preserving an already running older version that lacks the lease. Prohibited diagnostic helpers are excluded from that legacy check. No incumbent is terminated or activated. Concurrent new versions share the atomic lease. The [NSRunningApplication check](https://developer.apple.com/documentation/appkit/nsrunningapplication/runningapplications(withbundleidentifier:)) is a startup snapshot, not an atomic claim against an unmodified older version launching at the same time or afterward. There is no idle polling.

Batch and individual reads share error classification. Unsupported/no-value attributes may be absent; explicit CannotComplete remains a busy read. A generic failure may omit only optional AXDescription, as observed in TextEdit. Other failures and malformed typed values invalidate the snapshot. Omitting that label cannot satisfy Figma's required `Text` description or substitute for document, range, role or security evidence.

`AccessibilitySelectionPlan` requires a document and nonempty range with safe UTF-16 bounds and whole grapheme boundaries. A supplied selected-text string must match the document substring exactly in UTF-16, including decomposed characters. A supplied selected-range collection must contain exactly that one range. Missing/contradicting scope, malformed optional collections and multiple carets/selections stop before mutation. Static-text/document/cell roles are refused; the chosen text editor must additionally report AXValue editable. Figma's outside-edit TextArea with an empty description is refused even when its setters report supported.

Before mutation, a fresh snapshot must preserve focus, document, range, selected text and editor policy. The main continuation then rechecks input generation, process activation, secure input and physical modifiers. Word mode requires an empty selection and a caret at the token's end, retaining the 256-character/simple-character guard. Ordinary word mode embeds Backspace plus the first Unicode pair in one prebuilt batch without selecting or moving the caret; Spotlight uses the scoped native query path below.

`TextReplacementBackend` permits selected-fragment AXSelectedText replacement in the tested TextEdit AXTextArea, this process's NSTextView and the explicitly verified Spotlight search field described below, with a fresh settable-attribute check. Ordinary word mode, Figma, Electron and unknown native editors retain Unicode events. Spotlight word mode alone uses the proven plain-query value setter described below. The selected-text setter revalidates the exact selection and editability immediately before one AXSelectedText write; it never writes full AXValue. A failed setter or false success cannot fall through to keyboard input. Both transports share exact document/caret acknowledgement, one range restoration and final selection acknowledgement.

`UnicodeTextInput` embeds finished replacement text in private-source keyboard events with virtual key 0. Every payload is verified before reserving the attempt's one mutation. Ordinary events hold at most 20 UTF-16 units, preserving whole extended grapheme clusters; an oversized cluster is refused before mutation. An already-posted batch cannot be revoked, but cancellation stops unposted batches. An unverified mutation never retries deletion/input and never falls back to a clipboard transport.

Control characters require demonstrated editor behavior. The proven native selected-text backend in TextEdit and this process accepts literal LF/U+2028. Figma uses Return/Shift+Return only after public canonical-document proof; other external editors refuse these controls before mutation. CR, tab, other control scalars and U+2029 are refused everywhere. A framework may ignore Unicode event payloads and translate the virtual key instead; there is no universal per-field support query.

Figma paragraphs can have different AXValue and physical LF counts. Only its actual canvas text editor uses a canonical provider when raw AXValue contains LF/U+2028. `TextRangeDocumentPlan` obtains the full text through public AXStringForRange; it never strips or rewrites separators. Raw-value UTF-16 length is an upper bound, current selection/caret end a lower candidate. A proven Figma NoValue response alone permits bounded prefix search. Success must return exactly the requested UTF-16 length, followed by an empty end/0 result, explicit NoValue at end/1 and an identical repeated full-document read. The raw snapshot is then read again and must preserve all supplied document/range/text/policy evidence.

Discovery has a 120 ms operation budget, 32-query limit and 1 Mi UTF-16 upper bound. NoValue is not a generic macOS end-of-document contract: its interpretation is limited to the demonstrated Figma range implementation. CannotComplete, unsupported or malformed responses never become bounds. A cached length requires exact raw text and the same process session/element, and still repeats full text plus endpoint proof on every read. Real input/focus invalidation clears these text extent caches. Text-marker endpoint indices that the live probe reported as zero are not used.

Only this proven canonical snapshot enables Figma Return for LF and Shift+Return for U+2028. Unknown external fields retain single-line Unicode policy. Attachment-bearing documents containing U+FFFC are conservatively refused before mutation in both native and keyboard backends, preventing plain-text conversion from flattening embedded objects.

# Spotlight focus authority

On the tested macOS 27.0.1 host, Spotlight's search dialog belongs to `com.apple.campo` while NSWorkspace still reports Finder as the frontmost application. System-wide Accessibility identifies the actual focused owner and field. Version 0.1.10 correctly refused the ordinary target/frontmost mismatch, but that also prevented editing this search overlay.

`SpotlightSearchScope` permits that mismatch only after proving all of: the Campo bundle, AXTextField role, AXSearchField subrole, `SpotlightSearchField` identifier and an AXWindow/AXSystemDialog ancestor. Other Campo/Siri inputs cannot authorize that mismatch; all unverified owner/foreground mismatches remain refused. Ancestor discovery allows unsupported subroles on intervening containers, but never omits the required field/window identities. Every proof is worker-side, limited to eight ancestors and a 120 ms operation budget. The overlay context reads only the proven field; an absent range cannot redirect it to a parent or search result.

The initial NSWorkspace foreground PID must remain unchanged. Fresh system-wide focused-application and focused-element owners must match the original target PID, and the focused field and system-dialog window must be CFEqual to the originals. Exact field identity is reproved before mutation, acknowledgement, range restoration and bounds capture. AX calls do not run in the listening tap or block the main continuation. A late validation reply checks the active attempt and cancellation token again before continuing.

An integrated Spotlight word test dropped one of six fast Backspaces while updating search results, leaving `gпривет`. This overlay therefore uses no keyboard replacement or fallback. Selected replacement requires fresh AXSelectedText and AXSelectedTextRange setter availability, issues one selected-fragment write and one range restoration, and verifies both results.

Spotlight word mode requires fresh value/range setter capabilities and rederives the exact one-word replacement from the coherent original document and empty caret. It issues one AXValue write of that complete plain search query. This is the only production full-value replacement; ordinary editors never receive it. A value setter may move the caret to the query's end. Fresh exact expected document and a valid empty current caret must be acknowledged before one optional AXSelectedTextRange correction to the expected zero-length caret. Unexpected selections are never cleared. The correction does not renew the original 500 ms document/caret deadline and cannot be retried. Missing native capabilities refuse either mode before mutation. Its document and replacement must be single-line plain text: controls, line separators and attachments are refused. Neither backend sends Return or Tab.

Closing the overlay can change system-wide focus without changing the background frontmost application; fresh global proofs therefore remain necessary throughout the attempt. A focus change after the final proof cannot revoke an in-flight AX setter. Cancellation stops remaining work and acknowledgement must still confirm the exact document and caret/selection. This is a scoped compatibility policy, not a general permission to edit background applications.

# Replacement and selection acknowledgement

Every event source carries the synthetic marker. A batch's final key-down/up uses a distinct marker through separate `CGEventSource.userData`: live Quartz normalized per-event markers back to the original source marker. Only the matching final key-up received at the listening session tap releases the next batch, with a 500 ms watchdog and an additional 8 ms text-pair interval. A late marker cannot release a new batch. Receipt establishes system-queue passage, not editor handling.

After the stream, a fixed 500 ms polling budget must confirm the entire expected document, exact resulting caret and empty selection. A reply arriving after the deadline cannot confirm success. Only an explicit AXCannotComplete busy snapshot response permits another bounded read; focus, secure fields, policy changes and malformed evidence fail immediately. Word mode then completes. Selected mode first waits for physical modifiers to clear and restores its range once. Settable native ranges use one AXSelectedTextRange setter; Figma canvas (`AXTextArea`, description `Text`) never uses its false-success text/value/selection setters. Where keyboard restoration is needed, the expected document/caret is rechecked after the modifier wait.

A coherent original entire-document selection permits one Command+A. Partial fragments use exact grapheme counts in batches of at most 32 Shift+Left pairs. Repeated text never widens scope. Restoration is never retried. A separate fixed 500 ms AX budget must then confirm the expected document, exact range and every supplied selected-text/ranges attribute. Immediate reversal obtains a new snapshot; no previous selection proof is cached or reused.

A range setter is a synchronous cross-process message. Cancellation is checked before validation and immediately before the single setter. An in-flight IPC cannot be revoked by later input; fresh acknowledgement is required afterward. This is an OS boundary, not a claim of atomicity between applications.

Earlier independent probes found Figma AXSelectedText replacement reported success while its visible canvas and copied characters stayed unchanged. Production does not use that text setter. Figma's [plugin selection API](https://developers.figma.com/docs/plugins/api/properties/PageNode-selectedtextrange/) runs inside a Figma plugin, outside this utility's external AX transport. Partial canvas selection can redraw progressively; atomic visual restoration is not promised.

# Timing policy

All budgets are in `ConversionTiming`. Readiness deadlines stop waiting when evidence arrives; they are not mandatory sleeps.

| Budget | Value | Reason |
| --- | ---: | --- |
| Final Shift-release quiet interval | 90 ms | Conservative reduction from 145 ms; the explicit running/draining states protect interleavings during and after replacement. |
| One AX message | 120 ms | Bounds an unresponsive IPC without blocking UI; each newly acquired object is configured. |
| Canonical Figma document read | 120 ms, at most 32 range queries | Public endpoint/text proof; no nil/error-based normalization guesses. |
| Spotlight focus proof | 120 ms, at most eight ancestors | Public global owner, exact field and system-dialog identity; no generic foreground bypass. |
| Document/caret and selected-result acknowledgement | 500 ms each | Fresh exact AX evidence; no mutation/restoration retry. |
| Readiness poll | 20 ms | Temporary, only during an attempt; no permanent text/permission polling. |
| Unicode pair pacing | 8 ms after receipt | Gives the editor turns between bounded text chunks; queue delivery remains separate from editor proof. |
| Unicode/canvas batch delivery deadline | 500 ms | Waits for the matching final key-up at the session tap; target handling still requires exact document/caret/selection evidence. |
| Text/selection modifier-release deadline | 1,000 ms | Allows a rapid repeated Shift to release between batches or at selection boundaries; unchanged input/focus checks remain active. |
| Screenshot delivery budget | 55 ms | Allows typical warm captures while preventing a cold service from adding 100 ms. Geometry IPC is measured separately as AX work. |
| Reveal | 90 ms | Short fade after editor acknowledgement; never included as rendered completion. |
| Visible overlay watchdog | 650 ms | Releases the panel/image even if editor acknowledgement does not arrive. |

An AXObserver is optional according to Apple and notifications may be unsupported. This implementation uses bounded document/range/selected-text polling instead of registering several notifications on every gesture: observer setup adds IPC and cannot prove success. `ReadinessDeadline` tests demonstrate that repeated polling cannot extend the original deadline; only matching editor evidence establishes success.

`ReplacementOverlay` owns both a pending screenshot delivery and the current nonactivating, click-through panel. `PreparationResult.cancelled` cannot resume mutation; `.skipped` may proceed without an optional animation. Cancellation, timeout and late screenshot completion deliver at most once. Missing/zero geometry, multiline text, offscreen rectangles, secure input, old OS, missing permission and Reduce Motion skip capture. There is no guessed Figma geometry, full-screen screenshot, stream, OCR, disk image or network transport. A closed panel releases its view/image and presenter reference.

# Capability and idle-work bounds

Capability keys contain process identifier, launch session, bundle version and AX element identity. Positive capabilities expire within 30 seconds; unsupported results are short lived. A failed geometry request is scoped additionally to its range, expires after two seconds and is cleared by real input/focus. A canvas failure cannot blacklist a sidebar field. AXManualAccessibility activation is cached per process session for 60 seconds after success or three seconds after failure.

Once input monitoring and Accessibility permission are granted and the tap runs, no permission timer remains. Missing permission/startup triggers at most 15 two-second retries, then recovery occurs on app activation, menu opening or diagnostics opening. Diagnostic updates run only while the window is visible and stop on close/minimize. No text polling runs at idle.

# Window transfer — 0.1.13

`WindowMoveHotKeys` owns four exclusive Carbon `RegisterEventHotKey` registrations on the main thread, separate from the unchanged `listenOnly` conversion tap. The feature is enabled by default and has its own persisted menu toggle. Registration requires Accessibility trust, Input Monitoring, a running listener and at least two distinct `NSScreen.frame` rectangles. Disable, permission recovery, screen changes and termination reconcile the registrations; partial registration failure rolls back all four. No timer retries registration at idle. Disabling releases Option+Shift+arrows for native text selection. Text conversion may be paused while this listener remains active: `canStartConversion` includes the text toggle, and the burst gate cannot request or claim a disallowed conversion. Press/release tracking suppresses Carbon autorepeat; a busy transfer drops another press instead of queuing a window.

`WindowTransferPlan` is pure point geometry. Current AppKit screen rectangles convert to AX coordinates using `x = frame.minX`, `y = primary.frame.maxY - frame.maxY`; AX's origin is the primary screen's top-left, with Y downward. Largest window/screen intersection chooses the source, with display ID settling ties. A destination must lie beyond the requested source edge; perpendicular overlap is preferred, then geometric distance and stable IDs. Offset centers alone cannot turn a display directly below the source into a left/right neighbor. There is no wraparound. Ordinary windows preserve point size and relative placement within the remaining visible work area, shrinking only when needed and permitted. Frames within two points of full/half/quarter work-area geometry map to the same destination fraction. This infers geometry, not a native zoom/snap state, and retains no previous normal frame. A fitted ordinary window that becomes exactly filled can therefore map as filled on a later transfer.

`WindowMoveController` owns one attempt, original focused window, foreground PID, fresh screen/work-area snapshot and cancellation token. External AX calls are serialized off the main thread; own-window calls stay on AppKit's main thread. Each acquired element has a 120 ms messaging timeout. Strict role, minimized state, typed position/size and settable-attribute checks precede mutation. The system-wide focused application and its focused window must retain the original PID/element identity before each setter and through acknowledgement; no main-window/window-list fallback exists. Foreground changes, screen-change notifications and fresh topology mismatches cancel the attempt. In the tap callback, clicks, dragging, scrolling, typing and new modifier presses cancel the token synchronously; UI cleanup is deferred. The shortcut's Option/Shift releases and exact arrow repeats do not falsely cancel it. A new transfer first invalidates pending conversion and overlay state on main.

Preparation ends after 750 ms; a fixed two-second gesture deadline gates every setter, including the last worker-side check. Each issued step has a separate fixed 500 ms acknowledgement budget. A size reduction precedes movement; growth happens after movement to the destination. One final position correction is planned only when growth changes the anchor and is skipped when already satisfied. Every issued step uses fresh original-window/current-frame proof and one setter; read polling never repeats a mutation. Position acknowledgement also requires the expected size. Failure after a setter reports an unverified result, with no rollback. Public cross-process AX setters cannot make validation and mutation atomic, nor revoke a setter already in flight.

Own-window fullscreen refusal uses `NSWindow.styleMask.fullScreen`. External windows read a typed `AXFullScreen` value only when their public attribute list advertises it. A true state is refused; if no fullscreen state is available, a frame matching a complete display is conservatively refused. An explicitly known non-fullscreen filled frame remains eligible when the work area equals the display. This does not establish universal external Space-state detection. The feature sends no fullscreen/Space commands, activation calls, clipboard operations or synthetic keyboard events, and reads no window titles or text.

# Measurement and small optional features

`PerformanceRecorder` uses paired OSSignposter intervals for gate, AX operations, capture, event posting, confirmation wait, reveal and gesture-release-to-result. The mutation interval now includes text-pair pacing and queue receipts through the final batch. Each interval state is consumed once; an `EditorAcknowledged` event is emitted only after successful verification. Signposts carry fixed names/identifiers only. Numeric summaries retain 64 samples per metric in up to eight process-session/mode buckets. Median and p95 appear only after 20 confirmed samples in the same bucket. Failed/cancelled attempts do not enter confirmed-replacement distributions. AX duration accumulates AX work in the selected execution context; confirmation includes waiting for the editor. These timings overlap by design and must not be summed as disjoint wall-clock phases.

Editor acknowledgement means the expected document and exact resulting caret/selection were verified through AX. It does not measure the compositor's completed on-screen frame. Reveal duration reports the overlay, not target-app rendering. No user text, clipboard payload or pixels enter diagnostics or logs.

`LoginAtLaunch` reads `SMAppService.mainApp.status` and mutates registration only after the user presses its menu item. It never registers on launch. Status/approval/error display follows macOS; registration work is dispatched off UI. The diagnostics-copy button writes only the displayed status/timings plus app/OS versions to the user's clipboard, after an explicit click.

# Primary sources and SDK checks

The implementation was checked against these Apple sources and local SDK declarations (`AXUIElement.h`, `AXAttributeConstants.h`, `AXValue.h`, `CarbonEvents.h`, `CGEventSource.h`, `SCScreenshotManager.h`, `SMAppService.h`, and the `os.swiftinterface`):

- [Improving app responsiveness](https://developer.apple.com/documentation/xcode/improving-app-responsiveness): keep UI responsive and dispatch blocking non-UI work away from main.
- [AXUIElementCopyParameterizedAttributeValue](https://developer.apple.com/documentation/applicationservices/1461203-axuielementcopyparameterizedattr): reads a supplied parameterized attribute; it does not establish a universal NoValue end-of-text contract.
- [AXUIElementCopyMultipleAttributeValues](https://developer.apple.com/documentation/applicationservices/1462051-axuielementcopymultipleattribute): per-slot CFNull/AXError results can coexist with a successful batch.
- [AXUIElementSetMessagingTimeout](https://developer.apple.com/documentation/applicationservices/1459345-axuielementsetmessagingtimeout): timeout belongs to the configured object.
- [AXUIElementCreateSystemWide](https://developer.apple.com/documentation/applicationservices/1462095-axuielementcreatesystemwide): obtains the public system-wide object used for focused application/element discovery.
- [AXObserverCreate](https://developer.apple.com/documentation/applicationservices/1460133-axobservercreate) and the notification SDK declarations: optional notifications are not confirmation.
- [CGEventSource.keyState](https://developer.apple.com/documentation/coregraphics/cgeventsource/keystate(_:key:)) and [HID state](https://developer.apple.com/documentation/coregraphics/cgeventsourcestateid/hidsystemstate): sample key-down state separately from aggregate flags.
- [CGEvent.tapCreate](https://developer.apple.com/documentation/coregraphics/cgevent/tapcreate(tap:place:options:eventsofinterest:callback:userinfo:)): listening event tap uses its registered run loop.
- [NSScreen.screens](https://developer.apple.com/documentation/appkit/nsscreen/screens) and [visibleFrame](https://developer.apple.com/documentation/appkit/nsscreen/visibleframe): current screen layout and available work area; the array is refreshed for transfers and screen-change notifications.
- [Cocoa coordinate systems](https://developer.apple.com/library/archive/documentation/Cocoa/Conceptual/CocoaDrawingGuide/Transforms/Transforms.html): primary-screen bottom-left coordinates and points versus device pixels.
- [NSApplication.didChangeScreenParametersNotification](https://developer.apple.com/documentation/appkit/nsapplication/didchangescreenparametersnotification): cancel a pending transfer and reconcile registrations on display changes.
- [Apple Frameworks Engineer's Carbon hotkey clarification](https://developer.apple.com/forums/thread/763878): Option-only/Option+Shift registration was addressed in macOS 15.2 Beta 2; runtime refusal remains handled, with no event-tap fallback.
- [CGEvent.keyboardSetUnicodeString](https://developer.apple.com/documentation/coregraphics/cgevent/keyboardsetunicodestring%28stringlength%3Aunicodestring%3A%29): carries text in the event; Apple warns that a framework may ignore it and translate the virtual key instead.
- [CGEvent.post](https://developer.apple.com/documentation/coregraphics/cgevent/post%28tap%3A%29): posts into the event stream before the selected taps, without acknowledging editor consumption.
- [Timer energy guidance](https://developer.apple.com/library/archive/documentation/Performance/Conceptual/power_efficiency_guidelines_osx/Timers.html): temporary timers, bounded waits and invalidation when no longer needed.
- [OSSignposter](https://developer.apple.com/documentation/os/ossignposter): retain each begin state and pair it with exactly one matching end.
- [SCScreenshotManager](https://developer.apple.com/documentation/screencapturekit/scscreenshotmanager): the region screenshot API is guarded for macOS 15.2+; baseline remains macOS 13.
- [SMAppService](https://developer.apple.com/documentation/servicemanagement/smappservice), [register](https://developer.apple.com/documentation/servicemanagement/smappservice/register()), and [requiresApproval](https://developer.apple.com/documentation/servicemanagement/smappservice/status-swift.enum/requiresapproval): main-app login registration is explicit and can require a System Settings action.
