# SSwitcher

Небольшое приложение для macOS: **двойной Shift исправляет раскладку уже набранного текста (RU ↔ EN)**.

- Если есть выделение — преобразует весь выделенный текст.
- Если выделения нет — преобразует слово только когда курсор стоит сразу после его последнего символа. Например, `ghbdtn` → `привет`, `руддщ` → `hello`.
- После преобразования включает раскладку полученного текста.

Работает с левым и правым Shift: два коротких нажатия одной и той же клавиши за 300 мс. Shift с буквами, стрелками и другими модификаторами не запускает преобразование.

Начиная со сборки 173, только что набранное слово в MAX заменяется как в переключателях раскладки: SSwitcher стирает ровно набранные символы и печатает преобразованное слово. Выделения нет, замена занимает примерно 0,1–0,15 с от отпускания Shift. Уже написанное слово после клика или стрелок меняется одним запросом системных Services примерно за 0,3 с; временное выделение закрыто снимком окна. Полная проверка через Services остаётся только когда выделение могло быть.

## Сборка и запуск

Нужны macOS 13 или новее и Xcode Command Line Tools (`xcode-select --install`). Внешних зависимостей нет.

```sh
git clone git@github.com:TonyDanzza/SSwitcher.git
cd SSwitcher
bash scripts/build-app.sh
open build/SSwitcher.app
```

Для постоянного использования перенесите `build/SSwitcher.app` в «Программы» **до выдачи разрешений** и запускайте оттуда. Сборка предназначена для архитектуры Mac, на котором выполнена команда.

1. В настройках клавиатуры macOS включите английскую и русскую раскладки.
2. Нажмите **значок SSwitcher с двумя стрелками** в строке меню. Через пункты меню выдайте два разрешения в **Системные настройки → Конфиденциальность и безопасность**:
   - **Мониторинг ввода** — распознавать двойной Shift.
   - **Универсальный доступ** — получать выделение и положение курсора, заменять текст.
3. Если приложения нет в списке разрешений, добавьте его кнопкой «+». Если macOS попросит завершить приложение, запустите его снова.
4. В TextEdit наберите `ghbdtn` и дважды коротко нажмите Shift. Затем попробуйте преобразовать выделенную фразу.

Пункт «Исправлять по двойному Shift» ставит исправление текста на паузу. Выбор сохраняется между запусками. Пункт «Запускать при входе в macOS» включает или отключает автозапуск через системные объекты входа. Приложение не включает его самостоятельно. Если macOS требует подтверждение, меню открывает соответствующий раздел настроек.

## Перенос окна между дисплеями

В версии 0.1.13 **Option+Shift+←/→/↑/↓** переносит активное окно на дисплей слева, справа, сверху или снизу по его реальному расположению в macOS. Если в выбранном направлении нет дисплея, окно остаётся на месте. При расположении монитора над Mac используйте **↓** для переноса на Mac и **↑** для возврата.

Пункт **«Переносить окно: ⌥⇧ + стрелки»** включён по умолчанию и работает независимо от паузы исправления текста. Выключите его, чтобы освободить Option+Shift+стрелки для обычного выделения текста в редакторах. Выбор сохраняется. Сочетания регистрируются только при двух разных дисплеях, выданных разрешениях «Универсальный доступ» и «Мониторинг ввода» и работающем слушателе ввода; иначе меню показывает причину ожидания. Если сочетания заняты другой программой, регистрация отклоняется.

Обычное окно сохраняет размер в точках и относительное положение в рабочей области; координаты округляются до целых точек, поэтому окно не «уползает» при переносах туда и обратно. На меньшем дисплее размер уменьшается до доступной области, если программа разрешает его менять. Геометрия окна на всю рабочую область, ровно на её половину или четверть переносится в ту же долю соседнего дисплея; встроенное размещение macOS («Заполнить», «Слева», «Вверху слева» и т. п.) распознаётся с допуском 4 точки по каждому краю. Это определяется по координатам; прежний размер до уменьшения не запоминается. Если уменьшенное окно заняло всю рабочую область, следующий перенос трактует его как заполненное.

**В сборке 175 исправлен перенос на больший дисплей.** Сразу после переезда окна программа ещё 10–20 мс ограничивает его размер краем прежнего дисплея, поэтому половина экрана MacBook на мониторе получалась шириной 769 точек вместо 1280. Теперь увеличение окна после переезда ждёт 50 мс, а если результат всё же меньше нужного, размер задаётся ещё раз через 150 мс. Если macOS или программа поправили размер или положение (минимальный размер окна), в меню и окне проверки показывается «Окно перенесено; macOS или программа изменили его размер или положение», а перенос не бросается на полпути.

Полноэкранные окна в отдельных Spaces не поддерживаются: SSwitcher не выходит из этого режима и не переключает Spaces. Некоторые приложения не предоставляют доступное активное окно или игнорируют изменение его координат; результат тогда остаётся неподтверждённым. Окно фиксированного размера переносится только когда его можно разместить без изменения размера. Последний результат, план и итоговые координаты окна видны в окне «Проверить работу…».

## Как работает замена

Направление определяется по преобладающим русским или латинским буквам в тексте. Если букв поровну или их нет, используется текущая раскладка. При нескольких раскладках одного языка выбирается активная, иначе первая доступная. Соответствия символов читаются из установленных раскладок macOS, включая различия «Русская» и «Русская — ПК».

Без выделения словом считается непрерывный фрагмент до пробела, табуляции или переноса строки. Знаки препинания включаются: в неверной английской раскладке `[` и `;` могут означать русские буквы. Курсор должен стоять сразу после последнего символа слова. Внутри слова, перед ним и после пробела команда ничего не меняет и не подаёт звуковой сигнал.

Выделенный текст в TextEdit, встроенном тестовом поле и проверенном поле поиска Spotlight заменяется напрямую через Accessibility. В остальных редакторах замена передаётся через Unicode-события macOS: текст находится в самих событиях. Преобразование не читает и не изменяет буфер обмена, не отправляет Cmd+C или Cmd+V. Текст и выделение читаются через Accessibility; перед вводом приложение повторно проверяет их и активное поле. **В версии 0.1.14 после замены выделение снимается, а курсор остаётся в конце заменённого фрагмента — можно сразу продолжать печатать.** Следующий двойной Shift обрабатывает слово у курсора по обычным правилам; чтобы снова преобразовать весь фрагмент, выделите его вручную.

Непрерывная серия быстрых нажатий объединяется в одну команду после последнего отпускания Shift и паузы 90 мс. Во время замены новые команды игнорируются и не ставятся в очередь; продолжение серии после её завершения также не запускает новую замену до паузы. Если Shift нажали снова во время передачи текста, приложение ждёт его отпускания до секунды и продолжает ту же замену. Если результат остался неподтверждённым, новые замены блокируются до нового пользовательского ввода или перемещения курсора; подсказка строки меню предлагает проверить текст и выделить его заново.

В обычных редакторах слово у курсора заменяется без выделения: заранее подготавливается последовательность Backspace + Unicode-ввод. В проверенном поле Spotlight поисковая строка заменяется напрямую через Accessibility; при необходимости курсор возвращается в прежнее место без выделения слова. В этом Accessibility-пути команды Shift+стрелка не отправляются; отдельный Services-путь MAX описан ниже. После ввода сравниваются весь текст поля и точное положение курсора с ожидаемым результатом. Для составных Unicode-символов и слов длиннее 256 символов нужно ручное выделение.

Нет постоянного опроса текста активных приложений: чтение происходит только по двойному Shift. Таблицы преобразования кэшируются для двух направлений. Accessibility других приложений читается последовательно в отдельной очереди; собственное окно проверяется на главном потоке AppKit. Текст, диапазон и доступные данные выделения запрашиваются вместе. После ввода приложение проверяет весь ожидаемый текст и точный пустой курсор в конце замены, не повторяя удаление и ввод. После подтверждения повторное выделение и дополнительные стрелки не отправляются.

После выдачи разрешений постоянный таймер их проверки отключается. Пока разрешения отсутствуют, приложение повторяет проверку не дольше 30 секунд; открытие меню или окна проверки и активация приложения запускают проверку снова. Диагностика обновляется только при видимом окне и останавливается при его закрытии или сворачивании.

Вложение вне заменяемого фрагмента само по себе не запрещает преобразование. Его маркер и весь соседний текст должны остаться неизменными; текст выбранного фрагмента дополнительно проверяется через публичный запрос по диапазону. Выделение, захватывающее вложение, не преобразуется. Выделенный текст с переносами строк или слишком крупным составным символом может заменяться одним нативным действием, если обычный редактор подтверждает такую возможность. При отсутствии точных данных или нужной возможности SSwitcher отказывает до записи.

В Pages 15.4 поле документа появляется в Accessibility только после запроса вспомогательной технологии: до этого Pages сообщает фокус на области прокрутки. Начиная со сборки 177, при первом двойном Shift SSwitcher один раз просит Pages включить этот режим и ждёт до 0,4 с, пока сама Pages сообщит фокус на поле текста; дальше работают обычные проверки текста, курсора и подтверждение. Проверено на новом документе: слово в конце. Выделение, таблицы, надписи и колонтитулы в Pages не проверялись.

Для Electron-приложений SSwitcher включает дерево Accessibility при необходимости и временно кэширует результат. Если данные текста и выделения отсутствуют или противоречат друг другу, замена отклоняется до изменения. В Figma нужно войти в редактирование текста: поставить курсор строго в конец слова или вручную выделить символы. Объекты и слои без редактирования текста не преобразуются. Для переносов строк SSwitcher получает фактические символы через публичный AXStringForRange и подтверждает границу документа. Он не исправляет несовпадения Accessibility догадками: если доказать точный текст и диапазон не удалось, преобразование отклоняется до ввода. Доставка событий в системную очередь сама по себе не подтверждает изменение текста: приложение отдельно проверяет документ и пустой курсор в конце замены через Accessibility. Ввод не повторяется.

В Spotlight на проверенном Mac с macOS 27.0.1 окно поиска может получать ввод, пока Finder остаётся активным приложением. SSwitcher отдельно проверяет фокус самого поля поиска; закрытие окна или переход в другое поле отменяет ожидающую замену. Поддержка ограничена этим подтверждённым полем Spotlight: поля диалога Siri и другие системные окна требуют отдельной проверки.

В версии 0.1.12 подготовка Accessibility работает и для Electron с переименованным framework: приложение распознаётся по данным и структуре пакета. Проверки доступного поля, точного текста, диапазона и фокуса сохраняются. Пользователь подтвердил восстановление работы в установленном ChatGPT; это ручная проверка на данном Mac.

Повторный запуск версии 0.1.12 оставляет одну работающую копию: вторая иконка и перехватчик клавиш не создаются. Если уже работает старая версия, сначала завершите её через меню перед запуском новой. Старая версия, запущенная позже, ещё не содержит этой защиты.

## Раскладки и MAX

Текущая версия — **0.1.23, сборка 177**. SSwitcher использует обычные источники macOS — **ABC и Русская**. Дополнительные источники ввода не устанавливаются и не выбираются. Исходники отключённого эксперимента InputMethodKit сохранены отдельно; обычная сборка выпускает только приложение строки меню.

**Только что набранное слово.** Пока MAX активен, SSwitcher держит в памяти символы, набранные с последнего перемещения курсора. Клик, стрелки, сочетания с Cmd, Ctrl или Option, Return, Tab, Esc, Backspace через пробел и переключение приложения сразу стирают эту память. По двойному Shift слово заменяется одной пачкой клавиш: Backspace ровно по числу набранных символов, затем Unicode-ввод нового слова. Если слово состоит только из букв и перед ним был набран пробел, вместо Backspace отправляется один Option+Backspace. Общий буфер обмена, выделение, Services и Accessibility в этом пути не используются. Если ввести клавишу во время замены, оставшаяся часть не отправляется, и результат помечается как неподтверждённый.

В записях поля MAX с частотой 60 кадров в секунду слово из одних букв менялось за один кадр. Слово с цифрой или знаком препинания показывало один промежуточный кадр, где пропал один символ. Это отдельные наблюдения, а не гарантия для любого компьютера.

**Уже написанное слово.** SSwitcher отмечает, могло ли в MAX появиться выделение: перетаскивание мышью, двойной клик, клик с Shift, Shift со стрелками, сочетания клавиш и переключение приложения. Если выделения быть не могло (последним был набор, Backspace, обычная стрелка или одиночный клик), он сразу отправляет Option+Shift+Left и запрос Services: MAX передаёт слово слева от курсора, SSwitcher возвращает преобразованное. Пробел после слова, если курсор стоял за ним, сохраняется, курсор остаётся на месте. Если курсор стоит внутри слова, меняется только часть слева от курсора. Если менять нечего, выделение снимается стрелкой вправо. Снимок окна для скрытия выделения начинается сразу при втором отпускании Shift.

**Остальные случаи.** Выделенный текст и слово, когда выделение могло быть, идут прежним путём через системные **Services** с проверкой выделения и границы слова: редактор передаёт текст через отдельный служебный пакет и получает преобразованный ответ. Общий буфер обмена не читается и не меняется; Cmd+C и Cmd+V не отправляются. После замены курсор остаётся в конце фрагмента.

**Путь через Services медленнее.** На macOS 15.2 и новее при разрешённой записи экрана снимок скрывает временное выделение слова; без захвата выделение видно. Короткий путь показывал новое слово через 0,30–0,34 с после Shift, полный — примерно через 0,85 с. Получение ответа службой подтверждает передачу текста, но не весь документ редактора: MAX не предоставляет его через Accessibility. Автоисправление MAX может изменить слово после пробела, поэтому возврат Backspace через пробел делает слово неизвестным.

В строке меню отображаются время последнего двойного Shift и результат. «Текст заменён — подтверждено редактором» означает проверку документа и точного пустого курсора через Accessibility. Для MAX сообщение «Слово MAX перепечатано без выделения» означает доставку событий в MAX, «Текст передан нативному редактору MAX» — подтверждённую передачу Services-ответа. Ни то, ни другое не проверяет весь документ.

Пункт **«Проверить работу…»** показывает разрешения macOS, получение Shift, выбранный механизм и этапы замены. Запуск с `--check` открывает диагностическое окно на встроенном экране MacBook. Медиана и p95 доступны после 20 подтверждённых попыток в одном редакторе и режиме; время отрисовки на экране не измеряется. Кнопка «Скопировать диагностику» копирует отчёт без текста поля, содержимого общего буфера и снимков.

Приложение обрабатывает текст в памяти при преобразовании. Текст не записывается в настройки и не отправляется по сети. Постоянной истории набора, сетевых запросов и аналитики нет. Для MAX в памяти временно хранится только текущее набираемое слово, как описано выше. История исследования и результаты проверок — в [native-text-research.md](docs/native-text-research.md), [input-method-experiment.md](docs/input-method-experiment.md) и [validation.md](docs/validation.md).

## Плавная замена

На macOS 15.2 и новее пункт **«Плавная замена»** включает короткий переход на 90 мс. Для него нужно отдельное разрешение **«Запись экрана»**; запрос доступен в меню и в окне проверки. Без разрешения преобразование текста продолжает работать.

Перед заменой SSwitcher получает точные границы слова через Accessibility и делает один снимок небольшого участка через ScreenCaptureKit. Изображение временно закрывает удаление букв и исчезает после подтверждения вставки. Снимок существует только в памяти: файлов, видеопотока, записи звука и отправки по сети нет. Захват ограничен ожиданием 55 мс; при задержке выполняется обычная замена. Любой ввод, прокрутка или смена активного приложения убирает изображение и отменяет ожидающий снимок. Поздний результат захвата не может показать старый текст. Системная настройка уменьшения движения отключает эффект.

Анимация применяется только к тексту в одной строке с достоверными координатами, полностью видимому на одном экране. Для многострочного выделения и редакторов с неполным Accessibility используется обычная замена. **В проверенной версии Figma границы слова имеют нулевой размер, поэтому анимация там пока пропускается.** Это ограничение не отключает преобразование текста. Эффект не ускоряет сам редактор и может добавить время захвата и перехода.

Диагностика показывает время снимка или причину пропуска анимации.

В MAX скрытие внутреннего выделения работает отдельно от переключателя анимации: используется один снимок точных границ исходного окна, без затухания. Панель не получает фокус, не перехватывает мышь и не блокирует клавиатуру. Повторные Shift во время операции не снимают снимок; набор текста, клик, прокрутка, другие модификаторы и смена приложения снимают его. На захват отводится до 200 мс, а защитный таймер закрывает панель через секунду. Снимок не сохраняется на диск. Этот приём скрывает промежуточное состояние, но не ускоряет Services: измеренные отдельные замены занимали примерно 0,4–0,5 с.

## Ограничения MVP

- В версии 0.1.11 выделенные переносы строк поддерживаются в TextEdit и встроенном тестовом поле через прямую замену Accessibility. В Figma они требуют подтверждённого фактического текста через AXStringForRange; Spotlight и остальные приложения принимают только одну строку. Табуляции, CR, неподдерживаемые управляющие символы и поля со встроенными объектами U+FFFC также отклоняются.
- Преобразование требует согласованных текста, диапазона и признаков редактируемого поля через macOS Accessibility. Некоторые приложения не предоставляют эти данные или игнорируют Unicode-события. Терминалы, некоторые редакторы и игры могут не поддерживаться. Совместимость с каждым приложением требует ручной проверки.
- В защищённых полях и при Secure Keyboard Entry преобразование недоступно.
- Смешанное выделение преобразуется в одном направлении; автоматического распознавания языка каждого слова нет.
- Ошибка отображается в меню **SSwitcher** и его всплывающей подсказке, сопровождается системным звуком.
- По умолчанию сборка имеет локальную ad-hoc подпись. Для постоянной подписи можно передать `SSWITCHER_SIGN_IDENTITY` с именем своего сертификата Apple Development при вызове скрипта сборки. После смены подписи macOS может потребовать повторно выдать разрешения. Notarization для распространения пока не настроена.

## Разработка и проверки

```sh
swift test
bash scripts/build-app.sh
```

`SwitcherCore` содержит распознавание жеста, выбор направления и поиск слова с UTF-16 координатами, а также геометрию переноса окон. Приложение на AppKit использует слушающий `CGEventTap`, Accessibility и `UCKeyTranslate`; сочетания переноса регистрируются отдельно через Carbon. GitHub Actions запускает тесты, собирает приложение и прикладывает ZIP к запуску.

Архитектура, выбранные сроки и ссылки на документацию Apple описаны в [docs/architecture.md](docs/architecture.md). Автоматические и ручные проверки разделены в [docs/validation.md](docs/validation.md).

Исследование нативных API macOS, Caramba и открытых реализаций записано в [docs/native-text-research.md](docs/native-text-research.md).

Ручная проверка после выдачи разрешений:

1. В тестовом поле или TextEdit наберите `ghbdtn`, выделите его и дважды нажмите Shift. Должно получиться `привет` без выделения.
2. Сразу напечатайте `!`. Должно получиться `привет!`, без удаления преобразованного слова.
3. Для частичного фрагмента наберите `prefix ghbdtn suffix`, выделите только `ghbdtn` и повторите преобразование. После ввода `!` ожидается `prefix привет! suffix`.

Дополнительные ручные случаи:

- `ghbdtn` → `привет`, `руддщ` → `hello`; замена только в конце слова; начало, середина и позиция после пробела не меняют текст.
- Выделение одного символа, нескольких слов и текста с переносами строк, цифрами, emoji; после замены курсор в конце фрагмента без выделения.
- Левый и правый Shift; Shift + буква, Shift + стрелка, Command + Shift, долгое удержание и щелчок между нажатиями.
- Пауза, повторный запуск, отказ в разрешениях и их повторная выдача.
- TextEdit, браузерные поля и используемые редакторы отдельно.


## Иконки

Иконка приложения и монохромный знак строки меню используют общий векторный исходник `Sources/SSwitcher/BrandIcon.swift`. Знак строки меню — template image, адаптируемый macOS к теме и выделению. Иконка приложения включается в сборку как `Resources/AppIcon.icns`.

Для пересоздания размеров и ICNS:

```sh
swiftc Sources/SSwitcher/BrandIcon.swift scripts/generate-icons.swift -o /tmp/sswitcher-generate-icons
/tmp/sswitcher-generate-icons Resources
iconutil -c icns Resources/AppIcon.iconset -o Resources/AppIcon.icns
```
